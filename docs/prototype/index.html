TraeTool 界面规范

方案 A · 6 导航页 · WPF 980×680（最小 860×560）· 150% DPI

01 信息架构

采用方案 A：仪表盘 / 每日签到 / 账号管理 / 客户端切换 / 用量统计 / 设置。设置从原「账号管理」拆出，使账号列表职责单一，并给导航一个稳定的收尾项；「左导航 + 右内容」结构保持不变，六页常驻内存、切换仅改可见性。

05 组件规格

  • AccentButton：32px 高（大号 38px），主色实心，每屏仅一个；禁用态降为灰蓝并去掉阴影。
  • GhostButton：白底 + 1px 描边，悬停描边加深；用于刷新、检测、登录等次要动作。
  • Card / CardTitle：白底 14px 圆角 + 1px 发丝边框；标题 12.5/700，头部右侧放元信息。
  • NavButton：40px 高胶囊，选中态为深色微亮底 + 2px 主色内边线，不是整块高饱和填充。
  • Badge：18px 高，10px 字号；「当前」蓝、「客户端当前」绿。
  • 状态点：6px 圆点 + 文字，颜色只在状态点与文字上，不染色整行。
  • 输入：32px 高，聚焦时 2px 主色柔光环；时间 / 秒数用等宽数字。
  • 表格：表头吸顶、行高 30、偶数行微底纹、数字右对齐、预览列 Ellipsis。

文案颜色含义

08 交互说明

  • 导航：六页常驻，切换只改可见性；侧栏位置固定，选中态由 data-page 单一规则驱动。
  • 忙碌互斥：批量签到锁与切换锁互斥；锁定时相关按钮禁用并在 title 中说明原因；标题栏出现「后台任务执行中」药丸，任意页面可见。
  • 徽标：「当前」= 程序内查看的账号（P2 下拉切换）；「客户端当前」= 桌面客户端登录态（档案比对裁决），颜色与位置均不同。
  • 向导：五步 indicator，始终可取消；相似度 ≥0.85 时必须勾选确认才能建档；等待客户端登录时给出明确的「已完成登录」出口。
  • 托盘气泡：仅当批量签到实际获得积分 > 0 才弹「签到成功 +N」；全部跳过 / 失败不弹，避免「重复签到」误解。
  • 切换叙事：确认 → 日志逐步可见 → 成功/回滚；排障按钮弱化为幽灵样式并配 ToolTip。

09 WPF 落地备注

  • 保留现有样式语义名：Card / CardTitle / AccentButton / GhostButton / NavButton，外观按本规范重写即可。
  • 侧导航固定 212px，内容区 ScrollViewer 纵向滚动；860×560 下仪表盘底部卡片可滚动，不破版。
  • 趋势图由固定 520 Canvas 改为按容器宽度重算坐标（ActualWidth 变化时重绘），Y 轴保持 3 刻度。
  • 日志区使用等宽字体、逐行追加并自动滚动到底部；切换开始时把日志卡滚入视野。
  • 所有图标为本规范同款 Lucide 线性图标，落地时转为 Path 几何数据（stroke 1.75 / 24 网格）。

════════════════════════════════════════════════════════════════
一、产品概述
════════════════════════════════════════════════════════════════
 项目是 Windows 桌面工具，核心能力 5 项：
  1. 多账号管理：WebView2 内登录 XX 网页账号，凭据 DPAPI 加密保存。
  2. 每日签到：一键/定时为所有启用账号签到领积分；防重复签到是
     核心业务语义（详见第六节），界面必须准确表达各种跳过/冷却状态。
  3. 数据看板：剩余积分、今日获得、连签天数、签到日历、积分趋势、
     会员状态。
  4. 客户端登录态切换：把 XX 桌面客户端的登录数据（vault 档案）
     在多账号间备份/回写，实现"软件里切换账号后，打开客户端就是
     另一个账号"。
  5. 用量统计：按会话展示模型消耗（积分/tokens/明细）。

用户心智模型：日常只看仪表盘、偶尔点一键签到；配置一次自动签到
后基本无人值守；客户端切换是低频但高风险操作（会重启客户端），
需要清晰的过程反馈与安全提示。

二、技术与实现约束（设计必须兼容，不可违背）
════════════════════════════════════════════════════════════════
1. 技术栈是 WPF XAML，不是 Web。交付物若为视觉稿请用线框/标注
   描述，落地实现由开发转译为 XAML；不要输出 HTML/CSS 作为最终稿
   （可作视觉参考）。
2. 主窗口：默认 980×680，最小 860×560，居中。用户屏幕为 150% DPI。
   布局必须在最小尺寸下不破版；内容区允许纵向滚动。
3. 框架结构固定：左侧固定宽度导航栏（深色）+ 右侧内容区；
   五个页面常驻内存，切换仅改可见性（页面滚动位置等状态会保留）。
   导航项数量可增（见第三节方案 A），但"左导航+右内容"不可改。
4. 现有全局样式（设计可改外观、保留语义）：
   - Card        内容卡片容器（白底圆角）
   - CardTitle   卡片内小标题
   - AccentButton 主操作按钮（现为蓝色实心）
   - GhostButton 次要按钮（描边/幽灵）
   - NavButton   导航项（RadioButton 样式）
5. 现有色板（可整体替换，但需保持"深色导航 + 浅色内容"的对比关系）：
   页面背景 #F1F5F9；导航底 #1E293B；卡片白底；
   主强调 #2563EB；成功 #059669；警示 #D97706；危险 #DC2626；
   主文字 #0F172A；次文字 #475569；弱文字 #94A3B8；分割线 #E2E8F0。
6. 全部界面文案为简体中文。字体：微软雅黑/等宽(日志区)。
7. 已知环境限制（设计时规避）：
   - 无法依赖鼠标悬停才出现的关键信息（触屏/低 DPI 下 ToolTip 弱化）；
   - 复杂动画不必要，状态变化以颜色/文字/进度条表达即可；
   - 截图/视觉验证走窗口截图，设计稿避免依赖半透明叠加层。


════════════════════════════════════════════════════════════════
三、信息架构：页面划分（推荐方案）
════════════════════════════════════════════════════════════════

■ 方案 A（推荐）：6 个导航页
  导航自上而下：
    1. 仪表盘        —— 默认首页，概览与快捷操作
    2. 每日签到      —— 签到执行 + 自动签到设置 + 签到记录
    3. 账号管理      —— 账号列表 + 添加/登录/删除（纯账号职责）
    4. 客户端切换    —— vault 档案管理与切换执行
    5. 用量统计      —— 模型消耗明细
    6. 设置          —— 从"账号管理"页拆出的通用开关 + 关于
  理由：现"账号管理"页把账号列表和全局设置（开机自启/托盘/设备号）
  混在一页，信息密度高且职责不纯；拆出后每页职责单一，列表页更干净，
  也给导航一个稳定的收尾项（设置通常置于导航底部）。

■ 方案 B（保守）：维持现有 5 页
  设置区保留在"账号管理"页底部。若设计 Agent 认为 6 页过碎，
  可采用 B，但必须保证设置区与账号列表之间有明确的视觉分区。

下文按方案 A 写模块（P6=设置）；若选 B，把 P6 模块整体并入 P3 底部
即可，模块清单不变。

另有 3 类非导航界面（弹窗/覆盖层），见第五节。

四、逐页模块清单
════════════════════════════════════════════════════════════════
格式：【模块名】类型 / 内容字段 / 交互 / 绑定(VM属性) / 状态

──────────────────────────────────
P1 仪表盘（默认首页）—— 概览
──────────────────────────────────
【P1-1 页面顶栏】标题区+操作区
  - 左：页面标题「仪表盘」+ 当前日期（DateText）
  - 右：「刷新」次要按钮（RefreshCommand）、「立即签到（全部启用账号）」
        主按钮（QuickCheckinCommand）；Busy 时两钮禁用
【P1-2 全局状态横幅】文本条
  - 错误/警告信息（StatusMessage），空则隐藏
【P1-3 统计卡组】4 张并排卡片
  - 卡1 剩余积分：大数字（RemainingCredits）+ 所属账号（CurrentAccount）
  - 卡2 今日状态：已签/未签等（TodayStatus）
  - 卡3 今日总获得：+N（TodayReward）
  - 卡4 连续签到：N 天（StreakText）
  - 约束：4 卡在最小窗口宽度下仍须单行排布（数字可缩）
【P1-4 会员状态条】单行文本（MemberText）
  - 如"非会员"；来自客户端 entitlementInfo，空则隐藏
【P1-5 积分趋势卡】图表模块
  - 标题「剩余积分趋势（近 14 天）」
  - 折线+填充面积（LinePoints/FillPoints）、今日点标记(TodayX/Y)
  - Y 轴三刻度(ChartYMax/Mid/Min)、X 轴日期标签(AxisLabels)
  - 空态：「暂无趋势数据（签到/刷新后开始记录）」(HasTrend=false)
  - 注意：现为 Canvas 固定宽 520，设计可改为自适应宽度方案
【P1-6 签到日历卡】月历模块（宽约 300，与 P1-7 左右分栏）
  - 月份标题(MonthTitle) + ‹ › 翻月按钮(Prev/NextMonthCommand)
  - 周表头(WeekHeader) + 日期格(CalendarDays)
  - 格子状态三色：已签(checked，蓝底白字)/今天(today，黄底)/
    空白(blank，无底)；ToolTip 显示该日获得(Tip)
【P1-7 账号速览列表】右侧列表卡
  - 每行：账号名 + 「当前」徽标(IsCurrent) + 副行状态(Sub)
  - 整行可点击 → 跳转签到页并切换当前查看账号（OnAccountRowClick）
【P1-8 快捷签到入口】（已含于 P1-1 主按钮）
  - 语义：对全部"参与签到"账号执行批量签到

P2 每日签到 —— 执行 + 设置 + 记录
──────────────────────────────────
【P2-1 当前账号卡】签到页核心卡
  - 账号选择下拉(AccountChoices/CurrentAccountId)：程序内切换
    "当前查看"的账号，仅影响本页展示，不影响批量签到集合
  - 当前账号名(ActiveAccountLabel) + 剩余积分大数字(ActiveAccountCredits)
  - 说明文案：「切换账号只改变此处展示；一键/自动签到始终跑所有
    勾选参与签到的账号」——此文案语义必须保留（用户易混淆）
  - 右侧主按钮「一键签到（全部启用账号）」(CheckinCommand/CanCheckin)
【P2-2 状态卡】执行进度与结果（StatusMessage）
  - 批量执行中的实时进度行（如"正在签到 账号1…"/"等待 3.2s…"/
    "9074 冷却 65s 补跑中"）；需支持多行或滚动追加的视觉形态
【P2-3 自动签到设置卡】
  - 复选：开启每日自动签到(AutoCheckinEnabled)
  - 时间输入 HH:mm(AutoCheckinTime) + 提示「程序需在运行中」
  - 账号间隔秒数(CheckinIntervalSeconds) + 提示
    「执行时自动附加 ±2 秒随机抖动，规避风控」
【P2-4 签到记录卡】
  - 标题 + 账号筛选下拉(RecordFilters/SelectedFilterId)
  - 列表(Records)：时间(CheckedAt) / 账号(AccountName) /
    获得积分(Credits，绿色 +N)，最多 100 条
  - 空态：「暂无记录」
  - 注意：失败记录也入库（Reason），设计可考虑失败态行样式

P4 客户端切换 —— vault 档案管理（低频高风险页）
──────────────────────────────────
【P4-1 页面顶栏】
  - 标题「客户端切换」
  - 右：「检测客户端」次按钮(DetectClientCommand) +
        客户端路径输入框(ClientExePath，留空=自动探测，带 ToolTip)
【P4-2 客户端状态行】(ClientStatusText)
  - 检测结果：路径/是否运行中
【P4-3 操作状态行】(StatusMessage) —— 蓝色强调，切换过程反馈
【P4-4 档案列表卡】每行模块（与 P3 行结构相似但语义不同）：
  - 主行：账号名(DisplayName) + 「客户端当前」绿徽标(IsClientCurrent)
  - 副行：档案状态(ArchiveState，带状态色) + 档案详情(ArchiveDetail，
    如备份时间/文件数)
  - 说明行：身份备注(IdentityNote)——档案与客户端登录态的比对提示
  - 右侧操作组（4 钮，Busy 全禁用；每钮须配可见小字，见第十节）：
      [建档]    ArchiveCommand   —— 小字：备份客户端登录态（引导式
                                    向导，见 G4；未登录时小字变
                                    「需先在客户端登录一次」）
      [切换至此] SwitchToCommand  —— 小字：重启客户端并切换
                                    主操作，Accent 样式
      [排障]    VerifyCommand    —— 小字：校验档案完整性（低频）
                                    灰化/次级样式，title 仅作补充
      [删除]    DeleteCommand    —— 小字：删除该账号的档案
  - 档案状态色建议：有档(绿/中性)、无档(灰)、异常/待确认(橙红)
【P4-5 执行日志卡】
  - 顶部细进度条(Busy 时不确定进度)
  - 等宽字体日志区(Steps)，150px 高滚动，逐行追加：
    杀进程→快照→恢复→拉起→守护→回写 等步骤文本
  - 每个步骤须带小字注释或卡内图例说明（见第十节），如：
    杀进程=确保文件未被占用 / 快照=可回滚的备份 /
    恢复=写入目标账号档案 / 拉起=重启客户端 /
    守护=轮询确认登录态 / 回写=同步刷新后的凭据
  - 语义：让用户看到"切换没有卡死"，必须保留
【P4-6 底部说明文案】
  - 涵盖：建档引导入口说明、切换会关闭并重启客户端、失败自动回滚
    （快照位置 %TEMP%\traeswitch_rollback_*）、排障按钮定位
  - 文案较长，设计可拆成"提示条+展开详情"两种形态

════════════════════════════════════════════════════════════════
五、全局模块（跨页面 / 弹窗）
════════════════════════════════════════════════════════════════
【G1 左侧导航栏】（结构固定，样式可重设计）
  - 顶部：应用名「TraeTool」+ 副标题(TitleSubtitle，随页面变化，
    如显示当前账号/状态)
  - 中部：导航项列表（方案 A 为 6 项，含图标可选）
  - 底部：固定提示「关窗 = 收到托盘后台签到」
  - 选中态必须清晰（现为 RadioButton 深色底样式）

【G2 系统托盘与气泡】
  - 关窗最小化到托盘（CloseToTray 可关）
  - 气泡通知时机（业务约束）：仅当批量签到实际获得积分>0 才弹
    「签到成功 +N」；跳过/失败不弹，避免"重复签到"误解
  - 自动签到状态变化可更新副标题/气泡（低打扰）

【G3 登录窗口（WebView2 弹出窗）】920×720，不可缩放
  - 顶部深色提示条：「请在下方浏览器内登录 TRAE（手机号+验证码）。
    登录成功后本窗口会自动识别并关闭」+ [关闭窗口] 按钮
  - 中部：内嵌浏览器（WebView2）
  - 底部状态条：「正在初始化浏览器…」→轮询中→成功自动关
  - 设计点：初始化/等待登录的进度感、失败提示（可加"重新加载"）

【G4 建档向导（模态流程）】—— 用于「添加账号」成功后与
  首次「切换至此」无档案时的引导（两处入口共用同一向导）：
  步骤语义（必须传达）：
    ① 确认框：提示"须先在客户端登录过该账号一次"
    ② 打开 Trae 客户端 → 等待用户在客户端完成登录（等待态+可取消）
    ③ 关闭客户端
    ④ 与已有档案交叉比对：相似度≥0.85 弹警告「可能与另一账号
       档案重复，确认客户端当前登录的是该账号」→ 用户确认/中止
    ⑤ 备份建档 → 成功反馈
  设计要求：分步指示器（step indicator）+ 每步说明 + 取消入口；
  这是新手最容易卡住的流程，文案要口语化。
  小字要求（见第十节）：步骤条上每步除名称外须配一句小字说明
  （如「打开客户端 → 在客户端里手动登录该账号一次」），当前步
  在正文区展开详情；不能只靠步骤名（如光"交叉比对"）让用户猜。

【G5 确认/消息对话框】
  - 删除账号、删除档案、切换确认（"将关闭并重启客户端"）等
  - 统一三类：信息 / 警告(橙) / 危险(红)，主次按钮分明

【G6 全局忙碌互斥状态】
  - 两把全局锁：批量签到锁(BatchBusy)、切换锁(SwitchBusy)；
    互斥时其他页相关按钮必须禁用并给出原因文案
  - 设计建议：导航或顶栏提供全局"执行中"指示（如小进度环），
    让用户在任何页面都知道后台有任务在跑

六、关键业务语义（设计必须准确表达，不可美化掉）
════════════════════════════════════════════════════════════════
1. 防重复签到是产品红线。状态文案体系（P2-2/P3 副行共用）：
   - 「今日已签」——本地或服务器判定已签，绿色，正常态
   - 「未登录」——凭据缺失，灰/橙，需去账号管理登录
   - 「会话失效，请重新登录」——橙色警示
   - 「9074 限流冷却中 / 补跑中」——蓝色中性，非错误
   - 「签到失败（code=N）」——红色
   设计原则：跳过/已签 ≠ 失败；绝不能把"今日已签"渲染成红色错误。

2. 徽标体系（Badge），全站统一：
   - 「当前」蓝：程序内当前查看的账号（签到页下拉选定）
   - 「客户端当前」绿：桌面客户端登录态所处账号（档案比对裁决）
   - 两者语义不同，颜色必须区分，同页同时可能出现。

3. 会员状态：来自客户端本地 entitlementInfo（非网页接口），
   展示为「会员/非会员」，仅信息展示无操作。

4. 客户端切换的安全叙事：过程可见（日志卡）、失败可回滚（文案
   提及快照路径）、排障按钮低频弱化。页面整体色调可比其他页
   更"工具化/严谨"。

5. 9074 冷却补跑可能阻塞批次 60~75 秒，P2-2 必须显示倒计时/
   进度语义并提示"请勿重复点击"。

七、状态与空态清单（每页都要设计）
════════════════════════════════════════════════════════════════
每页至少覆盖：
  1) 常态（有数据）
  2) 空态（无账号 / 无记录 / 无趋势 / 无档案——文案已给，可配插画）
  3) 加载态（Busy：按钮禁用 + 进行中指示）
  4) 错误态（StatusMessage 横幅，含引导动作）
  5) 禁用态（互斥锁导致的按钮灰化 + ToolTip 原因）

全局：最小窗口 860×560 不破版；长账号名/长路径截断策略；
数字（积分）可能到 4 位数+小数，预留宽度。

════════════════════════════════════════════════════════════════
十、内联小字说明（硬性要求 · 2026-11-04 补充）
════════════════════════════════════════════════════════════════
10.1 为什么
  「建档」「登录」「排障」等是行话按钮，新用户看字面猜不出后果
  （建档=备份什么？排障是干嘛的？）。原型目前只把这些解释放在
  悬停 title 里——不可见、触屏无效、低 DPI 下难触发，与第二节
  约束 7-1 冲突。要求：**含义必须以可见小字常驻在控件旁**，
  title/ToolTip 只允许作补充，不得作为唯一说明。

10.2 呈现方式（三选一，按空间决定，可混用）
  A. 双行按钮 btn-stack：主词(粗) + 小字(11px 弱色)上下两行——
     适用于独立主/次按钮。原型已有参考实现：「立即签到/一键
     签到」下的小字"全部启用账号"，照此模式推广。
  B. 动作组脚注：列表行内多个小按钮并排放不下双行时，在该行
     操作组下方（或卡片头/尾固定说明行）给一行 11px 弱色小字，
     用「·」分隔解释各按钮，格式如：
     登录＝浏览器重新登录 · 建档＝备份客户端登录态 ·
     排障＝校验档案（低频）
  C. 状态联动小字：按钮小字随上下文变化（未登录/已登录、
     有档/无档），比静态文案更准确。

10.3 必配小字的控件清单（逐条出示意稿）
  位置            控件        小字文案（可润色，语义不变）
  ──────────────────────────────────────────────────────
  P3 账号行        ☐ 参与签到   勾选后进入批量签到
  P3 账号行        [登录]       打开浏览器重新登录
                               （未登录态：打开浏览器登录）
  P3 账号行        [删除]       移除账号及本机凭据
  P3 顶栏          [添加账号]   弹出浏览器登录新账号
  P3 顶栏          [刷新状态]   重新读取登录/签到状态
  P4 档案行        [建档]       备份客户端登录态
                               （无档且未登录：需先在客户端
                                登录一次）
  P4 档案行        [切换至此]   重启客户端并切换
  P4 档案行        [排障]       校验档案完整性（低频工具）
  P4 档案行        [删除]       删除该账号的档案
  P4 顶栏          [检测客户端] 查找客户端可执行文件路径

  P5 顶栏          [拉取最新]   联网获取所选时间范围的用量
  P1/P2 顶栏       [刷新]       重新读取本地数据库汇总
  ──────────────────────────────────────────────────────
  文案原则：动词开头、≤12 字、说清"点了会发生什么/有什么后果"；
  破坏性操作（删除类）小字必须点明不可逆或影响范围。

10.4 步骤类小字（同属本节要求）
  a) G4 建档向导：步骤条每步 = 步骤名 + 一句小字，例如：
       确认        —— 了解建档会关闭并重启客户端
       打开客户端  —— 在客户端里手动登录该账号一次
       关闭客户端  —— 释放文件占用，准备备份
       交叉比对    —— 与已有档案比指纹，防建错档
       备份建档    —— 生成该账号的登录态档案
     当前步在正文区展开详情；禁止只显示步骤名。
  b) P4-5 执行日志：日志卡提供步骤图例（首次执行前可见）或在
     每行日志尾部带小字注释：
       杀进程＝确保文件未被占用
       快照＝可回滚的备份
       恢复＝写入目标账号的档案
       拉起＝重启客户端
       守护＝轮询确认登录态保持稳定
       回写＝把刷新后的凭据同步回档案
  c) P2-2 执行状态：阶段提示配小字解释，如
       等待中 —— 账号间隔随机抖动，规避风控
       冷却补跑中 —— 服务端限流，请勿重复点击
  d) G5 对话框：危险确认的主按钮下加一行小字重申后果
     （如「删除后需重新建档才能切换」）。
